# Tests of the regular suites (core, apis, oidc, cmd, plugins) that are skipped when the
# test apps run on Postgres (CLAVIGER_TEST_DB=postgres, see tests/app_postgres.go).
#
# One test per line: the name of a top level test, a TAB, the reason. A test goes here only
# for a documented difference or because the test itself is written in SQLite SQL; the
# behavior it covers is then covered by tests/pgtests (named in the reason). Everything
# else in those packages must pass on Postgres. The list may only shrink.
#
# scripts/test_postgres_suites.sh turns this file into `go test -skip` and prints it.
#
# History: 35 entries at M4, 14 since M6. Made engine neutral (tests.ColumnType and
# tests.NormalizeQuotes translate the SQLite spelling an upstream test asserts; the view
# temp-table check asks the right catalog): the 13 *FieldColumnType tests, TestCollectionQuery,
# TestModelQuery, TestBindDbx, TestDeleteView and TestCreateViewFieldsWithDiscardedNestedTransaction.
# Passing as they are (the M3 backup work and the data dir based watchers): TestCreateBackup,
# TestNotifyWatcher_CollectionsUpdate and _SettingsUpdate (the latter two flake on macOS and
# in CI on SQLite as well; the script retries a failed test once).

# --- the test asserts the SQL text or the quoting of SQLite --------------------------------
TestRecordDelete	asserts the SQLite SQL text of the cascade queries (json_each); the Postgres SQL is pinned in tools/search/dialect_postgres_test.go
TestExpandRecordsQuerySkipDuplicatedIds	asserts the SQLite SQL text (json_each); the Postgres SQL is pinned in tools/search/dialect_postgres_test.go
TestRecordFieldResolverUpdateQuery	asserts the SQLite SQL text of the generated filter queries; the Postgres SQL is pinned in tools/search/dialect_postgres_test.go and the results are compared in tests/pgtests (TestRecordFilters)
TestRecordFieldResolverResolveCollectionFields	asserts SQLite JSON path SQL (json_extract) in some cases; compared on both engines in tests/pgtests (TestRecordFilters)
TestTableInfo	asserts the SQLite column types and defaults of the system tables; Postgres has its own (docs/datastores.md, "How data is stored")

# --- the test queries the SQLite catalog (sqlite_master, sqlite_schema) ----------------------
TestCollectionSaveViewWrapping	reads the view SQL from sqlite_master and asserts the SQLite subquery wrapping
TestSingleVsMultipleValuesNormalization	reads sqlite_master; the single <-> multiple conversion is covered by tests/pgtests (TestCollectionLifecycle) and core TestCollectionSaveIndirectViewsUpdate

# --- view queries written in SQLite SQL (user SQL runs as written, docs/datastores.md) -------
TestCreateViewFields	9 of its cases are view queries in SQLite SQL (square bracket quoting, a text column averaged, a loose GROUP BY, untyped expressions inferred as json where Postgres knows the type); the Postgres view cases are in tests/pgtests (TestViewCollections)
TestCreateViewFieldsWithNumberOnlyInt	the view query is SQLite SQL (total() aggregate)
TestDryRunView	one case ("select with invalid formatted field name") relies on SQLite accepting a column name that Postgres takes as valid; the rest pass, but the skip is per top level test
TestSaveView	selects * with an aggregate (SQLite is lenient about GROUP BY; the hidden _rowid_ column makes Postgres reject it)

# --- backups and the SQL endpoint: zip backups skip the database on Postgres ----------------
TestVerifyBackup	expects the manifest to list the tables of data.db and auxiliary.db; a Postgres archive has no data.db, its verification is reported as skipped (tests/pgtests TestBackupsOnPostgres)
TestSQLRun	asserts SQLite error text and column types; the Postgres behavior is in tests/pgtests (TestSQLEndpoint)

# --- the SQLite connection pools ------------------------------------------------------------
TestBaseAppDBDualBuilder	checks the separate read and write pools of SQLite; Postgres uses one pool
